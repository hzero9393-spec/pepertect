1. Product Context

Problem

Beginners in India cannot practice F&O trading without risking real capital. Existing paper‑trading tools are either oversimplified (no F&O) or paid.

Solution

Pepertect provides virtual currency, real‑time NSE pricing (Upstox primary / Yahoo Finance fallback), full equity/futures/options simulation, auto SL/Target exit engine, and guided learning paths.

Target Users

· College students (18–25) – no capital, need structured learning
· Working professionals (22–35) – have Demat but scared of F&O
· Aspiring traders (20–35) – want to test strategies realistically

Value Proposition

“Learn F&O trading with zero risk, real data, and real results.”

Out of Scope (DO NOT BUILD)

· Real‑money trading
· Mutual funds / SIP
· MCX commodities, forex/currency, international markets
· Algorithmic/API trading, social copying
· Brokerage integration, tax reporting, IPO bidding

4. Business Logic Rules

4.1 Registration

· Password: min 8 chars; strength meter (weak/medium/strong)
· Email uniqueness enforced at DB level → return 409 Conflict
· On success: bcrypt hash (cost 12), create User with tier=FREE, create Portfolio with balance = FREE_TIER_VIRTUAL_CAPITAL
· Issue JWT ({ userId, email, role, tier }, expiry) → store in localStorage

4.2 Login

· 404 if user not found; 401 if password mismatch; 403 if account disabled
· On success: re‑issue JWT, return user profile; client opens WebSocket

4.3 Google OAuth

· GET /api/auth/google → builds Google consent URL
· GET /api/auth/google/callback?code=... → exchange code, decode id_token for googleId/email/name/avatar
· Find‑or‑create: existing user → update googleId + last login; new → create with tier=FREE and default balance
· Error cases: access_denied → back to login; invalid code → 400; token exchange failure → 502

4.4 Trade Placement Validation (client + server, server is final)

· Quantity > 0 (integer; multiple of lot size for futures/options)
· LIMIT/SL orders: price > 0
· Sufficient balance/margin:
  · Equity = full order value
  · Futures = DEFAULT_FUTURES_MARGIN_PERCENT of contract value
  · Options (buying) = premium × lot size
· SL validation:
  · BUY: SL < current price
  · SELL: SL > current price
· Target validation:
  · BUY: Target > current price
  · SELL: Target < current price
· Tier check: FUTURES/OPTIONS require tier === PREMIUM → else 403 with upgrade prompt
· Market hours check (if ENFORCE_MARKET_HOURS=true): reject outside MARKET_OPEN_TIME–MARKET_CLOSE_TIME IST
· Brokerage: max(MIN_BROKERAGE, min(MAX_BROKERAGE, orderValue * BROKERAGE_PERCENT / 100))
· MARKET orders fill immediately at current price → create Trade
· LIMIT/SL orders stay PENDING until a tick triggers them

4.5 Order Lifecycle State Machine

```
PLACED → PENDING → TRIGGERED → FILLED → EXECUTED
                 ↘ EXPIRED
PENDING → CANCELLED
```

4.6 Auto‑Exit Engine (GlobalSLMonitor)

1. On app load, fetch all open positions with SL/Target set
2. Socket.io subscribes to price ticks for those symbols
3. On each tick:
   · BUY position: price <= stopLoss → SL hit; price >= target → Target hit
   · SELL position: price >= stopLoss → SL hit; price <= target → Target hit
4. On hit: POST /api/trade/square-off { positionId, triggerPrice, reason }
5. Server: close position, compute P&L, deduct brokerage, update Portfolio.balance, write Trade
6. Client: remove from monitored set, update UI, show notification
7. Edge cases:
   · WebSocket disconnect → on reconnect, re‑fetch open positions and check current price immediately
   · Market closed → pause monitoring, resume next open
   · SL === Target → only one square‑off executes

7. Routing & Client Architecture

· Single catch‑all route: app/[...slug]/page.tsx renders <AppShell />
· AppShell reads URL slug → maps to page key → sets useAppStore.currentPage → conditionally renders matching page
· Navigation updates URL via history.pushState (or Next router) for deep‑linking
· Desktop: collapsible sidebar with icons + labels, active route highlighted
· Mobile: fixed bottom nav bar (Dashboard, Stocks, Positions, Portfolio, More) + swipe gestures
· Page transitions: instant; use skeleton loaders instead of spinners
