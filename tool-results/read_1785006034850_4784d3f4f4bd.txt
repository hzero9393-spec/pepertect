    41→1. Product Context
    42→
    43→Problem
    44→
    45→Beginners in India cannot practice F&O trading without risking real capital. Existing paper‑trading tools are either oversimplified (no F&O) or paid.
    46→
    47→Solution
    48→

   276→4. Business Logic Rules
   277→
   278→4.1 Registration
   279→
   280→· Password: min 8 chars; strength meter (weak/medium/strong)
   281→· Email uniqueness enforced at DB level → return 409 Conflict
   282→· On success: bcrypt hash (cost 12), create User with tier=FREE, create Portfolio with balance = FREE_TIER_VIRTUAL_CAPITAL
   283→· Issue JWT ({ userId, email, role, tier }, expiry) → store in localStorage
   284→
   285→4.2 Login
   286→
   287→· 404 if user not found; 401 if password mismatch; 403 if account disabled
   288→· On success: re‑issue JWT, return user profile; client opens WebSocket
   289→
   290→4.3 Google OAuth
   291→
   292→· GET /api/auth/google → builds Google consent URL
   293→· GET /api/auth/google/callback?code=... → exchange code, decode id_token for googleId/email/name/avatar
   294→· Find‑or‑create: existing user → update googleId + last login; new → create with tier=FREE and default balance
   295→· Error cases: access_denied → back to login; invalid code → 400; token exchange failure → 502
   296→
   297→4.4 Trade Placement Validation (client + server, server is final)
   298→
   299→· Quantity > 0 (integer; multiple of lot size for futures/options)
   300→· LIMIT/SL orders: price > 0
   301→· Sufficient balance/margin:
   302→  · Equity = full order value
   303→  · Futures = DEFAULT_FUTURES_MARGIN_PERCENT of contract value
   304→  · Options (buying) = premium × lot size
   305→· SL validation:
   306→  · BUY: SL < current price
   307→  · SELL: SL > current price
   308→· Target validation:
   309→  · BUY: Target > current price
   310→  · SELL: Target < current price
   311→· Tier check: FUTURES/OPTIONS require tier === PREMIUM → else 403 with upgrade prompt
   312→· Market hours check (if ENFORCE_MARKET_HOURS=true): reject outside MARKET_OPEN_TIME–MARKET_CLOSE_TIME IST
   313→· Brokerage: max(MIN_BROKERAGE, min(MAX_BROKERAGE, orderValue * BROKERAGE_PERCENT / 100))
   314→· MARKET orders fill immediately at current price → create Trade
   315→· LIMIT/SL orders stay PENDING until a tick triggers them
   316→
   317→4.5 Order Lifecycle State Machine
   318→
   319→```
   320→PLACED → PENDING → TRIGGERED → FILLED → EXECUTED
   321→                 ↘ EXPIRED
   322→PENDING → CANCELLED
   323→```
   324→
   325→4.6 Auto‑Exit Engine (GlobalSLMonitor)
   326→
   327→1. On app load, fetch all open positions with SL/Target set
   328→2. Socket.io subscribes to price ticks for those symbols
   329→3. On each tick:
   330→   · BUY position: price <= stopLoss → SL hit; price >= target → Target hit
   331→   · SELL position: price >= stopLoss → SL hit; price <= target → Target hit
   332→4. On hit: POST /api/trade/square-off { positionId, triggerPrice, reason }
   333→5. Server: close position, compute P&L, deduct brokerage, update Portfolio.balance, write Trade
   334→6. Client: remove from monitored set, update UI, show notification
   335→7. Edge cases:
   336→   · WebSocket disconnect → on reconnect, re‑fetch open positions and check current price immediately
   337→   · Market closed → pause monitoring, resume next open
   338→   · SL === Target → only one square‑off executes

   766→7. Routing & Client Architecture
   767→
   768→· Single catch‑all route: app/[...slug]/page.tsx renders <AppShell />
   769→· AppShell reads URL slug → maps to page key → sets useAppStore.currentPage → conditionally renders matching page
   770→· Navigation updates URL via history.pushState (or Next router) for deep‑linking
   771→· Desktop: collapsible sidebar with icons + labels, active route highlighted
   772→· Mobile: fixed bottom nav bar (Dashboard, Stocks, Positions, Portfolio, More) + swipe gestures
   773→· Page transitions: instant; use skeleton loaders instead of spinners
